## Non-negotiable implementation constraints

- Never add GPU-disabling flags or force software rendering.
- Report hardware acceleration only from runtime evidence. Hide unsupported engine/backend/adapter fields rather than inventing values.
- Clearly report confirmed software fallback.
- Keep PTY reads, process management, and metric collection in Rust and off Tauri's main thread.
- Bound native queues, in-flight IPC batches, frontend queues, terminal scrollback, and shutdown drains. Never drop or reorder raw PTY bytes; coalesce only visual work.
- Do not emit one IPC message or frontend render per PTY read/chunk.
- Use one terminal/controller/render lifecycle per pane. Fit only visible terminals.
- Recover WebGL context loss once, then remain stable on xterm's supported fallback; never crash or loop.
- Schedule resize, fit, bounds, and visual output work at most once per animation frame.
- Animate only `transform` and `opacity`; apply `will-change` only during active transitions and remove it afterward.
- Suspend expensive presentation work for hidden, collapsed, off-screen, backgrounded, and minimized panes.
- Virtualize long terminal histories, logs, file trees, and process/session lists per the plan thresholds.
- Preserve raw process flow under visual pressure. Metrics must distinguish coalesced visual updates from PTY data loss.
- Do not weaken CSP, Tauri permissions, or production security/debug settings.
- Preserve unrelated work. Do not implement in the canonical checkout.
- Never commit without fresh verification. Do not push or merge unless Val explicitly asks.
