# Psyche Build v0.0.1 Multiplatform Release Design

## Status and scope

This design supersedes the `v0.1.0` version choice in the earlier release
distribution design. `v0.0.1` is the first public Psyche Build release. The
previous fork-era tags have been removed, and no GitHub Release currently
exists.

For this release, "all platforms" means the two product platforms that exist
in this repository:

- macOS as signed and notarized DMGs for Apple Silicon and Intel.
- iOS as an internal-only TestFlight build for iPhone and iPad.

Windows, Linux, Android, and public App Store distribution are not part of
`v0.0.1` and must not be advertised as supported release surfaces.

## Release identity

The signed Git tag is `v0.0.1`. The root `package.json` remains the
authoritative semantic version. The release-version tool must synchronize and
validate that version across:

- the root Node package;
- the native macOS package;
- the macOS Cargo manifest and lockfile;
- the Tauri configuration;
- the generated iOS Xcode project and its XcodeGen source configuration.

The iOS target uses `MARKETING_VERSION = 0.0.1` and
`CURRENT_PROJECT_VERSION = 1`. The semantic version identifies the public
release; the integer build number identifies the TestFlight upload and must
increase for any retry that uploads different bits.

The production iOS product identity is:

- Product name: `Psyche Build`
- Bundle ID: `ai.opencoven.psyche-ios`
- App Store Connect SKU: `psyche-ios`
- Primary language: `en-US`
- Minimum deployment target: iOS 18.0
- Distribution: TestFlight Internal Only

`project.yml` is authoritative for generated Xcode settings. Regenerating
`Psyche.xcodeproj` must be deterministic and leave no unexplained diff.

## Changelog and release notes

`CHANGELOG.md` begins with a single `0.0.1` entry dated on publication day. It
describes the complete first public product baseline rather than replaying the
removed Comux/fork version history. The entry covers:

- multi-agent workspace and worktree orchestration;
- Coven session integration, pairing, and remote pane controls;
- the native macOS shell, workspace panels, syntax-highlighted editor, and
  bounded virtualized diff viewer;
- themes, backgrounds, accessibility, notifications, and operator UX;
- the native iOS cockpit, bridge protocol, connection lifecycle, compact
  navigation, and demo-first limitations;
- release integrity, signed artifacts, checksums, TestFlight, and Homebrew;
- known limitations, including internal-only iOS distribution and the lack of
  Windows/Linux applications.

GitHub Release notes use the curated `CHANGELOG.md` entry as their body. The
workflow does not substitute an unreviewed generated commit dump. The same
entry supplies TestFlight's "What to Test" summary, shortened only to satisfy
Apple field limits.

## Apple and App Store Connect setup

Before the release tag exists, an authorized OpenCoven Apple administrator
creates:

1. An explicit Apple App ID for `ai.opencoven.psyche-ios`.
2. An App Store Connect iOS app named `Psyche Build` using that bundle ID,
   `psyche-ios` SKU, and `en-US` primary language.
3. An App Store Connect API key with only the access required to upload builds
   and manage internal TestFlight distribution.

If `Psyche Build` is unavailable as an App Store name, work stops for a new
user-approved name. The workflow must never silently choose a public product
name or a different bundle ID.

All production credentials live only in a GitHub Environment named `release`.
Repository secrets are not an accepted fallback. The environment uses required
reviewers and prevents self-review. It contains the existing Developer ID and
notarization values for macOS plus the App Store Connect issuer ID, key ID,
private key, Apple team ID, and any signing material required by the chosen
Xcode export path. Logs may report only whether a value is set, never its
contents.

## Coordinated release workflow

One protected workflow owns `v0.0.1` so the platforms cannot drift. Its jobs
are:

1. **Verify source**: require a public repository, an annotated tag with a
   verified signature, a stable `vMAJOR.MINOR.PATCH` name, exact version
   agreement, a tag commit on protected `main`, and a recorded verified commit
   SHA for downstream jobs.
2. **Verify product**: run the complete TypeScript/Vitest, package, Rust,
   frontend, Swift unit, iOS application, and iOS UI-test gates from that SHA.
3. **Build macOS**: independently build, sign, notarize, and verify Apple
   Silicon and Intel DMGs on native GitHub-hosted runners.
4. **Upload iOS**: archive `PsycheApp` for generic iOS devices, export using
   Apple's TestFlight Internal Only distribution, upload through App Store
   Connect authentication, and wait until build `0.0.1 (1)` is visible and no
   longer in an invalid processing state.
5. **Publish GitHub Release**: require both DMGs and the verified TestFlight
   upload, generate and validate `SHA256SUMS`, attach the curated changelog, and
   publish the release as latest stable.
6. **Notify Homebrew**: dispatch the OpenCoven tap updater as a separately
   retryable job after the public release is complete.

Every third-party GitHub Action is commit-pinned. Rust, Node, pnpm, Xcode, and
runner images are fixed or asserted strongly enough that a retry cannot
silently change the build toolchain.

## Retry and failure behavior

The release is fail-closed and idempotent:

- A missing secret, signing failure, notarization failure, test failure,
  version mismatch, or unexpected artifact stops publication.
- A retry may replace assets on an existing draft release.
- A retry encountering a published release must download and byte-compare the
  exact expected assets and checksums before treating publication as complete.
- A retry encountering TestFlight build `0.0.1 (1)` may reuse it only if its
  bundle ID, version, build number, and uploaded commit metadata match. A
  different binary requires build number `2` and an explicit release change.
- Homebrew notification can retry without rebuilding or republishing either
  platform.
- App Store Connect processing is polled for a bounded period. A timeout leaves
  the GitHub Release unpublished and provides the exact recovery command.

## Secret-safety and visibility sequence

The repository stays private throughout preparation. Immediately before it is
made public:

1. Run a redacted Gitleaks scan across all Git history and a separate scan of
   the exact publication tree.
2. Review every finding by path and rule without printing candidate values.
3. Confirm there are no tracked credential files, GitHub Releases, Actions
   artifacts, or caches containing release credentials.
4. Confirm the worktree is clean and the reviewed commit is the commit intended
   for `main`.

The initial full-history audit found only generic false positives in a public
cache identifier, keyboard-binding names, and vendored xterm lookup tables. No
provider-specific secret or credential file was found. This observation is not
a waiver: the audit must pass again against the final release commit.

Only after that gate passes may the repository become public. Secret scanning
is then enabled, an active `v*` tag ruleset restricts creation to release
managers and blocks updates/deletion, and branch protection for `main` is
confirmed before the signed tag is pushed.

## Homebrew delivery

The macOS application ships as `opencoven/tap/psyche-build`, a Homebrew Cask
with architecture-specific URLs and SHA-256 values sourced from the public
`v0.0.1` release. The updater refuses partial releases or checksum mismatch.
Release verification covers Cask style/audit plus install, launch, upgrade, and
uninstall behavior on Apple Silicon and Intel.

The Node CLI is not part of this public release and must not be described as an
npm-published package. A Homebrew Formula remains out of scope until the CLI is
distributed as a standalone binary.

## Completion criteria

`v0.0.1` is complete only when all of the following are true:

- the final source and history secret audits are clean;
- the signed tag resolves to the reviewed commit on protected `main`;
- both notarized macOS DMGs and `SHA256SUMS` are publicly downloadable;
- Gatekeeper accepts both macOS architectures;
- TestFlight shows `Psyche Build 0.0.1 (1)` as available to internal App Store
  Connect users;
- the GitHub Release renders the complete curated changelog;
- Homebrew install, launch, upgrade, and uninstall verification passes;
- public documentation advertises only the release surfaces that actually
  passed these gates.
